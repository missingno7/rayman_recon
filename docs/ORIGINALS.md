## What each asset tree is

### assets/GOG (user-supplied GOG install, 100 files)
- `RAYMAN.EXE`: banner `RAYMAN (US) v1.21`, `(C) 1994-1995 UBI STUDIOS, FRANCE` (no "UNPROTECTED"); PMODE/W 1.22 stub.
- `RAYMAN.BAT` (`RAYMAN.EXE save=C:\RAYMAN`) and `RAYMAN.CFG` are GOG/installer additions.
- Only `HMIDET.386`/`HMIDRV.386` equal the CD versions; all level/data files (`PCMAP/*`, `*.DAT`, `RAY.LNG`) have the
  same sizes as v1.12 but different contents (not yet analysed; possibly per-version encoding/checksums) [OPEN].
  `RAY.LNG` differs in size (18,727 vs 13,606).

### assets/DOS (installed DOS version, 100 files) and assets/DOS_CD (CD image)
- All 100 installed files are byte-identical to the CD's `RAYMAN/` subtree [PROVEN, inventory --compare]. The install
  is a plain copy (the CD has `PCMAP/<world>/RAYn.LEV`; same tree).
- `RAYMAN.EXE`: banner `RAYMAN (US) v1.12`, `(C) 1994-1995 UBI STUDIOS (UNPROTECTED), FRANCE`, file date 1996-03-20;
  PMODE/W 1.21 stub.
- CD `RAYMAN.bin/.cue`: MODE1/2352 data track + 25 audio tracks; ISO9660 volume `RAYMAN`, created 1998-03-04 - a
  later US re-release (The Learning Company branding: `GENESIS.INI`, `EREG/`, `AOL/` installers, `RLATER.EXE`).
  Other executables on the CD (`CONFIG.EXE` sound setup, `OS2_CONF.EXE`, `AUTORUN.EXE`, `START.EXE`,
  `GENESISB.EXE`) are not analysed [OPEN; CONFIG.EXE is a candidate secondary target].

### assets/PS1 (51-track BIN/CUE)
- Track 01 MODE2/2352, ISO9660 system id `PLAYSTATION`, created 1995-04-19; `SYSTEM.CNF` boots `cdrom:\SLUS-000.05;1`.
- `SLUS-000.05` SHA-1 equals rayman-ps1-decomp's target exactly [PROVEN] (US release).
- Track set came from a ROM site (`readme.html` is an ad); the data track hash is recorded, nothing else assumed.

## Never in git
No original file, decoded object, disassembly dump, or extracted asset is tracked. `build/oracles/<id>/` is
regenerated by `python tools/extract.py --all` and refuses unpinned inputs.
